# 伏笔 + 设定 模块彻底优化设计文档

> 2026-06-21｜目标:把「伏笔」和「设定」从**被动台账**升级为**主动写作引擎**——真正在写作时引导主编、把握走向与节奏。
> 全网研究依据见文末 Sources。

---

## 0. 核心诊断:为什么现在「太简单、帮不到写作」

两个模块今天的本质都是 **存储 + 展示**(被动库),不是 **写作引擎**。全网最好的工具(Novelcrafter/Sudowrite/Plottr)的共识是:

> **故事圣经必须是「AI 真正会读、按当前场景相关性注入」的结构化数据,而不是一个供人翻阅的库。**

对照我们的现状,两个根本缺口:

| | 现状(被动) | 应该(主动) |
|---|---|---|
| **伏笔** | 只记 埋→回收 状态;开着的全量塞给主编 | 带**读者效果**(惊讶/悬念/戏剧反讽)、**每个节点的具体引导**(埋多隐蔽、强化几次、回收什么效果);按**当前章相关性**只注入该照顾的 |
| **设定** | 存字段;写作时把**所有**角色/设定塞进去 | 按**当前场景相关性**只注入相关实体;富类型 + 别名 + 关系图谱 + 一致性校验 |

一句话:**信息不够结构化 + 不分场景相关性 + 没有"在第 N 章具体该怎么做"的引导**。下面分别彻底重构。

### 0.1 审计确认的两个「最大缺口」(代码全链路扫描后)

- **伏笔最大缺口 =「承诺线与写作没真正关联」**:伏笔只是孤立文本清单,**没有绑定到角色/实体**。主编写张三出场时,看不到"和张三有关的已埋伏笔",得手工搜;多条伏笔涉及同一故事线也不会自动群组;强化/回收的引导没接上人物弧光(char_states)。→ **作者看不见"下一步该回收哪条、和谁的故事线最配"**。
- **设定最大缺口 =「可用性与一致性没保障」**:编辑张三时看不到"张三第5章已瞎一只眼"(states 没进编辑视图/注入);力量体系规则注入了但**生成时违背不报警**(用了力量没付代价=穿帮);从正文抽到的"张三"和既有"张三"**没有合并流程**,只能删了重加。→ **作者不敢在写作时安心依赖设定**(怕改了设定和旧章冲突、怕力量用错代价)。

这两条把"看着挺全却没用"具体化了:**伏笔要连到人,设定要保一致**——下面的重构都围绕这两点。

## 1. 全网最佳实践(研究综合)

### 1.1 伏笔/承诺(craft)
- **Promise → Progress → Payoff(Sanderson)**:伏笔=对读者的承诺,要有进展(强化),回收要**超预期**("and then some")。
- **倒推法(work backwards)**:职业作家**先定回收(payoff)+ 想要的效果**,再回头找最佳的埋设点。← 我们现在是正着埋,缺倒推。
- **必须被铺垫(Weiland)**:"值得回收的东西,必须被铺垫";**每个重要回收 ≥ 2 个铺垫**;**三次法则**(重要揭示铺三次,可递进,如《人鼠之间》三起事件)。
- **隐蔽度(subtlety 1–5)**:草稿里铺厚,再精简到最强的几条;铺得太显→没惊喜,太弱→回收没着落。**别解释**(一解释就破功)。
- **距离(time gap)**:埋与回收间隔够大,读者"忘掉"再被回收击中。
- **读者效果轴(Hitchcock 炸弹理论)——这是点 4 的关键**:
  - **惊讶(surprise)**:读者和角色都不知道 → 爆炸瞬间 15 秒震惊。
  - **悬念(suspense)= 戏剧反讽**:**读者知道、角色不知道** → 15 分钟煎熬。
  - 所以每条伏笔要标:**想要什么效果** + **读者是否提前知道**(知道=戏剧反讽式悬念)。
- **契诃夫之枪 vs 红鲱鱼**:前者"出现就必须开火"(埋了必回收);后者"看着重要其实是误导"(故意的假线索,要管理、要在结尾澄清或转化)。
- **可建模的字段(直接来自 Weiland 的清单)**:回收事件、铺垫位置(可多个)、铺垫方式(对话/动作/语气/意象)、隐蔽度 1–5、回收位置、时间跨度。校验:每个大回收≥2 铺垫、铺垫先于回收、铺垫方式要多样。

### 1.2 设定/Codex(story bible)
- **Codex = AI 真正会读的结构化数据**(区别于自由笔记):quick facts(键值)+ rich text + tags/下拉 + **引用链接(实体间关系)** + 自定义字段。
- **实体类型**(Novelcrafter):人物 / 地点 / 设定(lore) / 物品 / **支线(subplot)** + 自定义类别。← 我们只有 人物/设定/母题,地点/阵营/物品/支线都挤在"设定+type"里。
- **Progressions**:把某字段绑到时间线某点,随剧情覆盖更新(防剧透 + 系列一致)。← **我们有**(char_states),但只用于人物。
- **智能索引别名**:识别名字/别称/绰号,自动链接、全局映射出场。← 我们有 appearances(靠引用),但没别名。
- **关系=知识图谱**:实体互相引用 → 连成图(喂关系图谱)。← 我们有 relations 但和设定库是两套,没打通。
- **按场景相关性注入(最重要)**:写某场景时,工具**自动只把相关的 codex 条目**喂给 AI(不是全塞),保证上下文窗口精准。← **我们现在是全塞**(所有角色+所有设定),这是最大效率/质量缺口。
- **人物 5 个承重字段**:want / need / 矛盾 / 声音 / 红线(我们已有)。

## 2. 伏笔彻底重构 →「承诺·伏笔引擎」

### 2.1 富数据模型(承诺线 thread + 节点 beats)

```
承诺线 thread = {
  promise:        对读者的承诺(灵魂,如「左眼藏着四十年前的命案」)
  ftype:          伏笔 / 悬念 / 契诃夫之枪 / 红鲱鱼 / 人物承诺
  intended_effect: 惊讶 / 悬念 / 戏剧反讽 / 不祥预感 / 好奇   ← 想达到什么读者效果
  audience_knows:  读者是否提前知道(true=戏剧反讽式悬念,Hitchcock 炸弹)
  weight:         主线 / 支线 / 点缀
  payoff_effect:  回收要达到的效果一句话(如「揭示时让读者重读前文细节而恍然」)
  links:          关联的实体[](角色/设定/支线)  ← 审计第一缺口:伏笔必须连到人/物
  status:         由节点推导(规划/进行/已回收/已弃/红鲱鱼待澄清)
}
```
**`links` 是把"伏笔"和"设定"两个模块焊死的关键**:
- 写张三出场(本章 POV/在场)时,自动把"links 含张三、且还开着"的承诺线推到主编面前(相关性注入,见 2.2);
- 设定库的张三详情页,反向列出"涉及张三的承诺线"(一处建、两处见);
- 关系图谱里,承诺线可作为一类边/节点挂到相关实体上(审计提到的"图里没有伏笔节点")。
```text
节点 beat[] = {                              ← 这是富度的核心,回答「在哪个节点怎么引导」
  chapter:    第几章
  kind:       plant 埋 / reinforce 强化 / misdirect 误导 / twist 转折 / payoff 回收
  guidance:   这一节点具体怎么写(如「藏在渡叔擦灯的动作里,别点破」)
  subtlety:   隐蔽度 1–5(仅 plant/reinforce)
  effect:     此处想要的局部效果(如「让读者起疑但说不出哪里不对」)
  anchor:     正文锚点(链到具体段落,可跳转)
  done:       是否已写
}
```

要点:
- **倒推法支持**:先填 promise + intended_effect + payoff(章+效果),再规划 plant/reinforce 节点(系统提示"重要回收建议≥2 铺垫、三次法则")。
- **红鲱鱼**:`ftype=红鲱鱼` 的线,结尾前必须有 `kind=澄清` 或转化,否则告警"假线索没收尾"。
- **戏剧反讽**:`audience_knows=true` 时,注入主编的提示变成"读者已知 X、角色不知,写出煎熬感"。

### 2.2 写作时如何真正引导主编(按相关性 + 节点注入)

不再把所有开着的伏笔全塞。改成:**写第 N 章时,只注入"本章有节点要做"+"该回收/超期"的线,并带上该节点的 guidance**:

```
【本章承诺·节点指令(照此处理,勿无视)】
· [埋·隐蔽度2] 阿砚的船渡图 → 本章:让图一角不经意露出,藏在收拾包袱的动作里,别让任何人评论它
· [强化·第3次] 渡叔的左眼 → 本章:第三次提及(三次法则),可让旁人多看一眼、渡叔回避
· [回收·戏剧反讽] 三不渡规矩 → 本章回收:读者早知阿砚会破规,角色仍在挣扎,写出"明知不可为"的重量
· [红鲱鱼·待澄清] 哑女是河神 → 已埋8章,本章或下章宜澄清/转化,别让它烂尾
```

这才是"有效帮助":主编拿到的是**这一章具体要在哪几条线上做什么、达到什么效果**,而不是一张清单。

### 2.3 UI 彻底优化(回应点 1/2/3)

- **点 2(挤一小块 → 全页)**:点任一承诺线,**整页切换**到「承诺线详情页」(像实体详情那样占满中区),不再底部挤一条。详情页含:promise/类型/想要效果/读者是否预知 + **节点编辑器**(逐节点加 plant/reinforce/payoff、写 guidance、设隐蔽度、链锚点)+ 健康校验 + 跳转正文。
- **点 1(时间线信息少/不好操作)**:时间线每条线的节点用不同形状(埋○/强化·/误导?/回收★),**悬停显 guidance 摘要**,点节点直接编辑;顶部加**筛选**(按类型/状态/超期/主线)、**健康总览条**(X 条悬空、Y 条超期、Z 条红鲱鱼待澄清);底部承诺密度(已有)。可平移缩放(已复用 ReactFlow)。
- **点 3(列表不能新增/看详情)**:列表视图加「+新建」、每行点开**同一个全页详情**(与时间线共用),不再是死表格。

### 2.4 健康校验器(写作护栏)
- 每个 payoff 是否 ≥2 铺垫;铺垫是否都先于回收;隐蔽度是否过显;
- 悬空(埋了无回收计划)、超期(开太久无进展)、红鲱鱼未澄清;
- 承诺密度告警(某章开着太多=读者超载;中段全空=节奏塌)。

## 3. 设定模块彻底重构 →「活的故事圣经」

同样的逻辑(结构化 + 相关性注入 + 富引导)套到设定。

### 3.1 富类型 + 富字段
- **一级实体类型**:人物 / **地点** / **阵营** / **物品** / 设定·规则(lore) / 母题 / **支线**(支线≈承诺线,可与伏笔引擎打通)。← 把现在挤在"设定+type"里的拆成一级,各有专属字段模板。
- **每类字段** = quick facts(键值)+ rich text + tags + **引用链接(关系)** + 自定义字段。沿用人物 5 承重字段(want/need/矛盾/声音/红线)。
- **别名/绰号**:每实体可填别名,索引出场、注入时识别(渡叔=老渡=摆渡的)。

### 3.2 关系打通(设定库 ↔ 关系图谱)
- 实体的"引用链接"就是关系边 → 设定库里建的关系**直接喂关系图谱**(AtlasView),不再两套。关系也可带"自某章起生效"(已有 valid_from_chapter)。

### 3.3 按场景相关性注入(最大提升)
- 写第 N 章时,**不再塞全部角色/设定**,而是按相关性打分只注入**相关实体**:
  - 信号:本章大纲/上一章提到、最近 K 章出场过、被"钉住(pin)"、与本章 POV 人物有关系边。
- 给作者一个**「本章在场」面板**:自动列出相关实体,可手动 pin/移除,所见即注入。← 直接解决"上下文窗口被无关设定挤占"。

### 3.4 一致性校验器(审计:设定最大缺口=一致性没保障)
- **力量体系规则强制**:生成/审稿时检测"用了力量却没付代价/越过限制"→ 实时 flag(乱世铜炉判据2:用力必有代价)。writing.py 已注入规则,但缺"违背即报警"。
- 矛盾(同一字段前后冲突)、**契诃夫**(埋了重要设定从未用→提醒)、**未立先用**(某设定首次出现却没在设定库)、Progressions 防剧透(已有)。
- **编辑张三时就近显示其 states/出场**(审计:编辑视图看不到"第5章已瞎一眼"),改设定前先看到旧章约束。

### 3.5 实体合并(审计缺口:抽取候选与既有重复无合并)
从正文抽取(ExtractPanel)出"张三",若与既有"张三"重名/别名匹配 → 给"**这是原有张三(合并)/ 新建**"二选一,而不是只能删了重加。别名索引(3.1)是合并判断的基础。

### 3.6 UI
- 实体详情已是全页富表单(本会话已做);补:关系编辑、别名、pin、出场矩阵、逐实体"与主编讨论"(已有)。

## 4. 落地路线(已审计,精确到 file:line)

**后端(SCHEMALESS 增量,不动旧数据):**
1. 伏笔:thread 加 intended_effect / audience_knows / payoff_effect;`echoes` 升级为 `beats[]`(kind/guidance/subtlety/effect/anchor/done)。新增/改 REST + MCP(主编可建/改)。
2. writing.py:把"全量开着的伏笔"换成"**本章节点指令**"注入(2.2);角色/设定换成"**相关性注入**"(3.3)。← 这是真正帮到写作的核心改动。
3. 设定:character/setting/motif → 富类型(地点/阵营/物品/支线一级化),加别名、引用链接;relations 与设定打通。
4. 校验器:伏笔健康(2.4)+ 设定一致性(3.4)端点。

**前端:**
1. 承诺线**全页详情 + 节点编辑器**(替掉底部挤的小块);时间线加筛选/健康条/节点悬停;列表加新增+详情。
2. 设定:类型扩展、关系/别名/pin 编辑、「本章在场」面板。

## 5. 一句话总纲

> 让伏笔和设定都变成**"在第 N 章,具体告诉主编该做什么、达到什么效果"的引导系统**,而不是写完之后才来登记的台账。结构化 + 相关性注入 + 逐节点引导,是把"看着挺全但没用"变成"真能帮到写作"的关键。
