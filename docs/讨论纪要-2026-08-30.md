# 讨论纪要 · 2026-08-30

## 结论

需求作为设定仪器是对的，作为完整小说作法不够。规划已补三处：写下一场必须有本场任务；允许省略场；故事时间 / 谁在哪一场学会 / 第几次写入正史，分开。

「已发生」和「此刻才写入」**不是组 3 的能力**。Graphiti / Semantica 只有双时态字段的形状（世上为真 vs 系统记录），时间是墙钟、读是检索、写是抽取。EverOS / HyperMem / TiMem 连这两列都没有。v1 在自己的场（第几次写入正史）与情状窗口（故事时间起止）上实现。

产品面：[`设定图-v1.md`](./设定图-v1.md)。世界库落地：[`plans/2026-08-30-设定图-Narra底座.md`](./plans/2026-08-30-设定图-Narra底座.md)。

## 补进规划的写法

```mermaid
flowchart LR
  task[本场任务]
  sit[本场规定情境]
  fill[模型填草稿]
  you[人改补]
  write[点写入正史]
  world[这一刻的世界]
  world --> sit
  task --> sit
  sit --> fill
  fill --> you --> write --> world
```

- 历史 → 穿帮检查（不许穿帮）。本场任务 → 写哪一场。两件事不合成。
- 场面要演；省略场有时长、可换地、不演动作/对白/内心。
- 晚到事实：新场的本场变化把情状窗口指回更早故事时间；不改旧场的动作/对白/内心。修订旧戏是另一条路。

## 组 3 对照（文件）

- Graphiti：`vendor/graphiti/graphiti_core/edges.py` 的 `EntityEdge`：`valid_at` / `invalid_at` / `created_at` / `expired_at`
- Semantica：README「valid_time is when true in the world; recorded_at is when you learned about it」
- 两者都没有角色知情这条轴，都不能替代「算出某一故事时间的世界」

## v1（同日后补）

实现认 [`设定图-v1.md`](./设定图-v1.md)。收口了原先会写岔的几处：不另开情节表；算出这一刻时同一列全部在场都算进去；伏笔最多 5 条按人/地选取；写入正史 / 改已写入正史的场 / 晚到窗口三件事分开；伏笔单独一类。

伏笔是对读者的欠账，不是情状。场上标埋/收；写下一场侧栏只给相关未收。上场价值转折一行。不做情绪分、不做全页伏笔台账。

## 世界引擎规划对不对（同日续，夜再收口）

**能算清这一刻的世界，并不能替你写出下一场好戏。** 边界写在 [`世界引擎.md`](./世界引擎.md)。

- 算出这一刻、三个时间、同一列全部在场、草稿不算正史：对。能演进的是世界，不是下一场戏。
- 好的场面来自本场任务 + 人改动作对白内心 + 模型吃到的那一份规定情境。把整份世界塞进模型太宽；价值转折空不挡写入正史；伏笔按近不按急。
- 不把这件事补成仪表盘。本场规定情境已写入 v1：知情差、当场利害、相关未收伏笔、上场价值转折、本场默认谁会看见。仍不代人决定写哪一场。

## 写下一场看全世界还是限知（同日续）

**两层都要，不是二选一。** 已写进 v1 九条后的刀与抽屉。

「吃全部历史」= 算出这一刻时不要只沿一个人。本场任务站全知 + 知情差；动作/对白/内心遵循每人已经知道的。不能只用某一个人的限知当下一场的全部上下文，否则写不出反讽和「走进圈套」。
