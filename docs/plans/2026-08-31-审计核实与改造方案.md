# 设定图：审计核实与改造方案

日期：2026-08-31。本仓本机路径：`<legacy-repo-root>`。  
对照外来审计做了文件级核对。不在本机跑全量编译或浏览器套件。

对人说话用日常用语。代码路径只在文末。

---

## 先说三句

1. **设计方向对。** 分开写设定、不替人写下一场、三个时间分开、点了才进历史——这些该留下。
2. **“建设清单全绿”不可信。** 很多通过记录是同一份日志复制出来的。真模型填场根本没接上。
3. **代码不是零。** 分场条、写入历史、算出这一刻、一本一文件的世界库都已经有。过时文档里的“还没写代码”不要再当现状。

不要推倒重来。先止血证据，再让填场真能调一次模型，再补作者能看见的缺口。

---

## 审计对在哪

### 证据被复制，观感虚高

- 建设清单里 1.1 到 1.20 共二十份运行记录，**字节完全相同**。内容是别人机器 `~/...` 上一次 `cargo test` 的整包输出，复制进二十个文件夹。
- 2.1、2.2、3.1、4.8、5.2、5.3、5.5 共用同一句 `wave2 ALL PASS`。
- 2.3、2.4、2.5 共用同一份打开书记录。
- 3.3 与 4.1 共用同一份。
- 54 个证据目录里，真正内容不同的只有 26 份。其中不少还是一行摘要，不是逐步点击记录。

建设规则自己写过：过关必须是真业务路径，不能拿库内测试充数。这一点审计成立。

**但不要说成“底下没有测试”。** `vendor/narra/tests/setting_wave1.rs` 里确实有按渡口故事写的库内检验（草稿不进这一刻、同人两地挡住、标黄仍可写等）。假的是“二十项各自独立跑过”的包装，不是这些函数都不存在。

6.1 那份逐步点击记录（空书 → 建人建地 → 写入历史 → 规定情境 → 假模型填场 → 同人两地挡住 → 导出）是现有证据里最像真跑过的一份。改造时以它为样板，不要整盘作废。

### 真模型填场是空壳

- 假填场接口写死：“（假模型）为「…」走了一步”。
- 真填场接口：没密钥返回缺密钥；**有密钥也直接返回没实现**（说当前环境不能出站）。
- 4.3-live 标成 blocked，理由是没密钥。就算配了密钥，以现在的代码也调不出去。
- 审计说“招牌能力零验证”成立。4.3 绿的是假模型。

### 文档滞后

README、交接文件仍写“还没写代码 / 产品代码未开工”。仓里已有三十多次提交、分场条页面、Rust 接口、一书一文件的库。  
交接里“库里还没有写入历史事务、没有三时钟”也过时了——这些表已经建了。

### 叉进来的底座只用了外壳

设定图自己的人物、列、场、在场、伏笔走一套新表，没有用底座原来的人物 / 地点 / 知情表，也没有用它的反讽查询、一致性引擎。实际用的是：嵌入式库连接、迁移、测试夹具、编译。

“叉了一个大项目当启动器”这个判断方向对。不等于新写的算出这一刻 / 写入历史 / 穿帮检查不存在。

### 中文全文与库版本没对齐方案

方案要求左栏中文全文、中文切词，并点名不要用英文词干。  
实际：底座自带检索仍是英文词干；设定图左栏搜名字是**整表拉出来再看字串包不包含**。短中文名（如「阿禾」）现在能搜到，并不是真空。缺的是方案里那套中文全文，不是“中文名完全搜不到”。

向量模型默认英文。Cargo 锁的是 Surreal 2.6，文档多处按 3.x 全文能力写。建设清单还写了第二份全文迁移文件，仓库里没有这个文件。声称覆盖中文全文的那一项，实际测的是“两本书不串数据”。

### 建模正在变厚，有的还没真正干活

- 增量折那条路径编出来了，编译告警说没人用。
- 物化缓存号称省计算，实现却是**每次先全量算一遍，再跟缓存比**。缓存现在不省时间，只多一份可能漂的副本。
- 伏笔在折的时候能改成已兑现 / 已作废，但没有“从已兑现跳回未收就算非法”的红线检验。
- 知情穿帮只标黄不挡住。库内有一条标黄用例。点击路径上没见到黄点真出现。实现里还有一段算完丢掉的死代码，标黄本身偏脆。

铜炉的教训（库里很全、作者用不上）这里要防的是：**先证明作者在分场条上用得上，再加层。** 不是现在立刻拆掉算出这一刻。

### 改良项（审计说得对，级别没那么高）

- 删已正史：有影响清单字样和序号不重排；没看到删完后再问这一刻、确认那一笔变化真的没了。
- 文档互相转写同一条约定，改一处容易漏。完整方案已是集大成，其它文档应改成指针，别再各写一版现状。

## 审计说过头的地方

1. **“产品自称的核心能力从未真正跑通”**——若核心指**真模型填场**，对；若指**算出这一刻 / 写入历史 / 同人两地挡住**，不对。后者代码在，6.1 点击记录也走到了挡住和看这一刻。
2. **“中文支持是真空”**——全文检索方案没落；左栏按名字包含搜，短中文名可用。不要按“阿禾搜不中”去排第一优先级。
3. **“54 项通过全是仪式”**——复制很严重，但 6.1 以及若干独立点击摘要不像同一份 cargo 输出。要分级处理，不要整盘烧掉。
4. **“Narra 官方能力基本没被复用”所以必须立刻二选一（迁回旧表或拆成薄库）**——那是中期结构选择，不是当前产品能不能写设定的阻断。v1 先冻住：设定图只走自己这套表，不再往底座旧表上堆功能。

文学层判断（只保证世界不穿帮、不替人写出好戏、三个时间分开、伏笔是欠读者的账）与产品面真源一致，本核实同意。

## 改成什么样

打开分场条，作者应能相信三件事：

1. **写进历史的，后面问这一刻真能看见；没点的，看不见。**
2. **点「模型填场」时，出来的是这次模型根据本场任务和规定情境写的草稿，不是写死的假句。** 仍须人改、仍须人点写入历史。
3. **建设清单上写“过了”，对应的是这一次跑出来的记录，不是复制粘贴。**

界面上人仍看见：这场转了什么、谁知道谁不知道、读者还欠哪一响。不改成替你写小说的流水线。

## 怎么改（按顺序，做完一项再下一项）

### 1. 证据止血（先做，再谈完成度）

- 建设清单里 1.1–1.20 改口：这是**库内故事检验**，不是作家点击。保留测试文件，删掉十九份重复运行记录，只留一份指向那一次（或以后重跑的一次）真实输出。
- 共用同一行“ALL PASS”的项：要么补上本项自己的逐步记录，要么改回未完成。禁止再复制。
- 新规则：一项过关 = 自己的剧本 + 自己的断言 + **内容与别项不同**的运行记录。记录里要有可核的观察（书名、场次编号、挡住原因原文），禁止只写 pass。
- 6.1 的逐步记录当样板。

做完之后：打开证据目录，不应再出现二十个相同哈希。

### 2. 让填场真的调一次模型

- 真填场接口有密钥时必须真正请求配置的模型，把本场任务和规定情境送进去，收回动作 / 对白 / 内心建议。
- 没有密钥：明确失败，不当成通过。
- 有密钥也不准自动写入历史。
- 验收：配好密钥，打开渡口书，写「阿莲来找东西」，点填场，格子里出现的不是“（假模型）走了一步”；再点写入历史，问这一刻才看见这场。

假填场可以留作没密钥时的开发开关，但不得再给“真填场已完成”打勾。

### 3. 作者能看见的缺口（不推翻主面）

按这个顺序补，每条都要能在分场条上点出来：

1. **知情穿帮标黄真的出现。** 阿福已写入“刀在抽屉”，阿莲对白说出这句话：侧栏或卡片标黄，仍允许写入历史。现在库内有、点击没有；实现里那段空转要修掉。
2. **伏笔状态不许瞎跳。** 没埋就兑现、已兑现再埋，要挡住或明确标错。现在折的时候直接改状态，没有这道门。
3. **删一场已写入的历史之后，再问那一刻，那场引起的变化必须没了。** 现在多半只断言清单字样和编号。

限知、规定情境已经按方案做了。不要为“用得上”再加仪表盘。先让上面三件事在屏幕上发生。

### 4. 中文与库版本：先说清，再决定要不要升

- **现在不必为搜「阿禾」去升库。** 左栏包含匹配够用。
- 若仍要方案里的中文全文：单独立项。同时决定 Surreal 跟 2.6 还是升到文档说的 3.x，禁止一边写 3.x 能力、一边锁 2.6。
- 英文向量模型：设定图主路没用它搜场。先不要为它装大模型。用不上就标“未用”，避免再当成已交付。

### 5. 底座怎么处：冻住，不立刻拆

- v1 继续只用设定图自己这套表算出这一刻。
- 禁止再把底座旧表（人物/地点/知情原表）接进分场条。
- 增量折若没人用：删或标明死代码，不要再写“全量与增量等价已交付”。
- 物化要么真能跳过全量计算（命中则不再全算），要么先关掉，避免第二份世界悄悄漂。
- 整仓瘦身（丢掉未用的底座能力）放到真填场和证据止血之后，不当当前阻断。

### 6. 文档跟代码对齐

- README / 交接 / 完整方案开头：删掉“还没写代码”。写清本机路径、已经能打开分场条、真填场未接、证据有复制问题。
- 建设清单里“中文全文”那一项改回未完成或改写成它真正测过的“两书不串”。
- 其它文档只保留指针，不再各写一版“当前状态”。

## 怎样算做完

可以宣布“审计改造第一期完成”仅当同时满足：

1. 证据目录没有整包复制；1.x 不再冒充点击。
2. 配了密钥后，填场能调通一次，且不会自动变成历史。
3. 分场条上能点出：知情标黄、伏笔瞎跳被拦、删历史后这一刻变了。
4. README 与交接不再说“没写代码”。

后做仍后做：整页出场表、连线图。不拿它们挡第一期。

---

## 明确不要做什么

- 不要为了分数再刷建设项。
- 不要把铜炉代码、铜炉库、铜炉环境变量引进来。
- 不要改成按人物一条线往下写。
- 不要让模型决定写哪一场，或一贴草稿就进历史。
- 不要在本机（内存很紧）跑全量编译、全量浏览器套件、常驻第二套库。重活放到已有验证环境，或用户点名的机器。
- 不要为“用满 3.x”先升库。

---

## 风险

- 真填场接上后，模型仍可能复述世界、不带转折。那是文学验收，不是接口通了就完。接口通只证明“不是空壳”。
- 关掉物化或删增量折，可能暴露现在被缓存挡住的不一致。这是好事，要当回归而不是意外。
- 证据改口会让“完成度百分比”下降。以诚实为准。

---

## 要不要开干

要。按上面 1→2→3→6 的顺序。4、5 不挡第一期。

第一期已在 2026-08-31 落地（证据改口、真填场接口、标黄/伏笔门/删历史后这一刻）。本机未跑全量编译。真填场要在配好密钥的机器上点一次才算现场验过。
