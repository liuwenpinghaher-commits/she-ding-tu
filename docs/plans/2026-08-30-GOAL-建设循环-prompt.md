## 怎么跑（人执行）

工作目录必须是：

```text
/Users/miaoma/Downloads/写作设定项目
```

在本目录开 Grok Build CLI（TUI）。确认 `goal.enabled` 为开。需要无人值守时先 `/always-approve`。然后：

```text
/goal 严格执行 docs/plans/2026-08-30-GOAL-建设循环-prompt.md 从「角色」一节到文末。本文件即 objective。未生成 docs/plans/设定图-建设循环.md 并自检通过前，禁止写产品代码。
```

**主循环用 `/goal`，不要用 `/loop` 当建设。** 依据：Grok CLI `~/.grok/docs/user-guide/04-slash-commands.md`。`/goal` 是一个未完成目标跨多轮，宿主做独立证据审查，复现不了就继续或 pause。`/loop [间隔] prompt` 是按时间重复同一段话（轮询 CI、探活），最短 60 秒、7 天过期，**没有「矩阵做完才停」**。建设 32+ 切片是前者。用 `/loop 5m` 再跑本文件会打断正在写的切片、空转、把未完成标成完成。

合盖怕会话死：外环才可以 `/loop 15m /goal status`，看到 paused 再 `/goal resume`。不要把整份建设 prompt 挂进 `/loop`。

不要另开铜炉仓。本机世界文件、`.env`、密钥不进 git。

本 goal **预授权持续跑**：不要问「要继续吗」。一轮只做矩阵里序号最小的未完成切片。做完写证据、勾选、**commit 并 `git push origin HEAD`**（远程 `https://github.com/liuwenpinghaher-commits/she-ding-tu`）。卡死（同一切片失败满 3 次且说不出下一次改哪几个文件）才 fail-loud 停；blocked 也要 commit+push，让远程看得到失败现场。合盖后新会话 `/goal resume`，或 `/goal` 写「接着 `docs/plans/设定图-建设循环.md` 第一个非 done 切片」。

### LLM：建设代理 ≠ 产品填场

算出这一刻、穿帮、规定情境、写入正史 **禁止**调模型（世界引擎、完整方案 F08）。**不要**把 API key 写进本文件、goal 正文或 git。

Grok CLI 登录只够**建设代理**自己说话。产品里「讨论格子 / 模型填下一场 / 丢草稿拆场」要另接一套，用本机环境变量（`.env` 已 ignore）：

## 阶段 B：循环（实现 → 真 E2E → 必要时改方案 → 再 E2E）

```
读取 设定图-建设循环.md

  判断是代码错还是方案错
  代码错 → 改代码
  方案错 → 改完整方案 / 世界引擎 / Narra 底座 / 建设循环.md 对应节
           （九条、唯一库、人点才写入正史、不替人选题：不准改）

若通过:
  写 e2e/evidence/<id>/

  push 失败则切片不能算 done，先修远程再继续
不要问人要不要做下一项；立即取下一 todo
```

### B.1 什么叫「真正的 E2E」（强制）

**算：**

- 波次 1：通过公共写入口提交一场完整的「渡口」戏，再用算出这一刻 / 规定情境 / 知情 / 穿帮检查查询，断言文学结果。可以没有浏览器，但不能没有「场」。可以有 Rust 检验作辅证，**不能单独当作过关**。
- 波次 2–6：用 Playwright（或同等）**像作家一样点**：创建书、填本场任务、写入此框、写入正史、点列、拖标记、确认变更。然后断言 **UI 与 Narra 一致**（齿色、侧栏规定情境、库里的边和 `status`）。截图只作附件。
- 最终 `6.1`：一条脚本从头走到 F40 闭环，中途不断开重灌假数据充数。

**不算（出现即本切片未过）：**

- 只有单元测试 / `cargo test` 全绿
- 只有「页面 HTTP 200」「组件能渲染」
- 只截一张静态图
- 演示页 `demos/stripboard-v1.html` 假数据充数
- mock 掉 `world_at` 再断言 mock
- 用向量 / 模型「看起来像」规定情境
- 查询语句自己滤一遍当「这一刻」而不走同一份 `world_at`

模型填场（`4.3`）允许用固定假模型返回结构化格子，但 **写入此框 / 写入正史 / 算出这一刻** 必须走真路径。

### B.2 文学教授闸（每切片 done 前默念）

至少能回答切片里写的问题。通用三问：

1. 这一步之后，**下一场的人**看见的世界，和分场条上已正史的场，是不是同一条故事轴？
2. 有没有哪一次**没人点**写入正史或确认变更，世界却变了？
3. 知情、在场、伏笔有没有被「方便的实现」写错（被提及当目击、草稿当历史、建议当选题、档案小传冒充情状窗口）？

答不出 → 切片不能 done。

对照完整方案 §8.13.7：写入正史半场历史、预览变正史、点名当目击、墙钟当学会时、档案数组从头即真、串书、列号当分钟、缓存里人还在渡口、假成功、同 id 删建——任一条被证据撞上，切片失败。

### B.3 改方案的边界

E2E 暴露方案空洞时 **必须改方案再测**，这是本 goal 的设计，不是失败。

| 可以改 | 不准改 |
|---|---|
| 完整方案里未写死的交互细节、建议目录缺项、索引 / 事务实现落点 | 九条 |
| 建设循环切片的拆法、E2E 剧本（改完要重跑） | Narra 是唯一世界库 |
| 世界引擎检验表增补（与纯函数合同一致） | 写入正史必须人点；确认变更必须人点 |
| Surreal 用法（仍须对上写戏，禁止为用而用） | 规定情境 / 历史不指定写哪一场 |
| | 与铜炉无关；禁止第二份 fold |

改了方案：在完整方案对应节写「因切片 \<id\> E2E：…」，并改建设循环该切片的剧本，然后 **重跑该切片 E2E**。

### B.4 架构最优（实现时不许偷）

- 算出这一刻：`world_at` / `fold` 纯函数；物化是缓存。落点：`vendor/narra/src/services/world.rs`（不要塞进 `temporal.rs`）。
- 规定情境：`given_circumstances`；不含伏笔建议、不含结构建议。落点：`vendor/narra/src/services/circumstances.rs`。
- 穿帮检查：`constrain` 纯函数；挡 / 标黄按 F12。落点：`vendor/narra/src/services/constrain.rs` 或扩展 `consistency.rs`。
- 写入正史 / 确认变更：一条 SurQL 事务；多语句逐条校验。落点：`vendor/narra/src/services/canon.rs`。
- 在场 / 知情：RELATE，不是 JSON 袋。
- 三时钟可查询：`clock_from/to`、`commit_seq`、`status`。
- HTTP 薄包只读 `GET /world?t=`：物化 → 未命中则 `world_at` → 回填。禁止前端再算一遍。
- 禁止：就地 `current_world`；LIVE 自动写正史；HNSW 排规定情境；`fn::world_at` 当第二份 fold；原生 VERSION 冒充三时钟；同 id 删建；`work_id` 混多书。

依据：`docs/世界引擎.md`、完整方案 §8.13 / 8.13.8。
