# 设定图：GitHub 对标与改造方案

打开书，人该一眼看懂：这是哪本书、这一场发生什么、世界因此怎么变。下面先列真实搜到的仓库，再逐项对照我们现在怎么做。GitHub 上别人做得更好、又不推翻已拍板的，才改。已经更好或本来就不该抄的，写「无改造」。

星数以 **2026-09-01** GitHub API 为准。每条仓库都打开过页面或 README，打不开的没写进来。

## 第 2 步 · 逐项审计

每项四段：现状 / GitHub 最佳例 / 差距判定 / 改造与优先级。

### 1. 书架（建 / 开 / 切 / 删书）

**现状。** 空书架一句「还没有书」+ 大按钮新建。有书时卡片网格：书名、主脑、写到第几列、最后一场名字、正史/草稿数、上次打开。按上次打开新到旧。⋯ 里打开 / 书的设定 / 导出 / 删书。删书必须手打书名。顶栏还能下拉切书。文件：`apps/web/src/pages/ShelfPage.tsx`、`NewBookPage.tsx`、`Dialogs.tsx` 删书框。

**GitHub 最佳例。** plotbunni `NovelGridView.jsx`：卡片网格、搜书名、卡上改名、删前确认。bibisco 项目列表。

**差距判定。** 删书手打书名 **已优于** 普通确认框。最近打开排序、最后一场名字 **已达最佳**。差在：书多了不能搜（plotbunni 有搜）；卡上不能改名（设定页写了「改书名只改显示，目录名不变」，改名会动目录，**不改**）。

**改造。** P1：书架加搜框，滤书名 / 主脑 / 最后一场。改名无改造。

### 2. 分场条主面

**现状。** 打开书就是一行一场。卡上色带=逻辑线，薄条=过滤不是藏。疏中密改卡上写多少字。拖列边界改故事时间，走确认变更。文件：`apps/web/src/board/Stripboard.tsx`。

**GitHub 最佳例。** manuskript 索引卡；plotbunni `PlanView.jsx` 幕/章/场卡。没有一家按「故事时一列一场 + 确认才改钟」。

**差距判定。** **已优于** 普通索引卡：我们有正史/草稿、确认变更、逻辑线只是看法。vis-timeline 不当主面，已拍板。

**改造。** 无改造。

### 3. 时间标尺 + 全书细条

**现状。** 顶上细条每列一齿，颜色：正史 / 草稿 / 空 / 省略。本页窗口齿描边。点齿跳窗口起点。悬停出这一列场名。标尺点列看这一刻。文件：`Stripboard.tsx` 的 `#minimap`、`#ruler`；时间轴看法 `LookRail.tsx` 的 `TimelineLook`（按全书/回目/天，拖条被挡住）。

**GitHub 最佳例。** vis-timeline：缩放、条目、拖范围。FleshNote World History Timeline 拖关系。

**差距判定。** 有差距。已拍板写了「点齿或**拖框**跳本页窗口」。现在只能点齿，不能拖本页那一框。时间轴看法已正确挡住拖钟。不把 vis-timeline 接进主面。

**改造。** P0：细条上按住本页窗口那几齿拖，松手后窗口起点跟着走，列数不变。

### 4. 加列 / 减列 / 合并 / 挪列 + 确认变更

**现状。** 顶栏加列；更多里减列/合并/换位。拖列边界侵入。都先出建议和影响清单，人点「确认变更」才写库。未确认可预览。文件：`Topbar.tsx`、`Dialogs.tsx` `#confirm-dlg`、`store.tsx` `preview` / `confirmChange`。

**GitHub 最佳例。** planka / wekan：拖完立刻改。NovelForge：先预览再确认落库。

**差距判定。** **已优于** 看板（他们无确认，我们有账要算）。确认框有影响清单和建议，和 NovelForge「先预览再确认」同类。

**改造。** 无改造。不学看板无确认。分歧见文末。

### 5. 写下一场（任务必填 → 模型填 → 写入此框 → 写入正史）

**现状。** 没本场任务，写下一场按钮灰。假模型填场、讨论、写入此框、写入正史分开。正史必须人点。已正史要点「改这一场」才动。文件：`Topbar.tsx`、`ScenePage.tsx`、`store.tsx` `writeNext` / `commit`。

**GitHub 最佳例。** NovelForge：字段流式生成 → 确认才落库。plotbunni：AI 建议进场景框，仍是人点。

**差距判定。** **已达最佳 / 局部已优于**（他们常一键写进稿；我们多一道「写入正史」）。不抄自动正史。

**改造。** 无改造。

### 6. 丢一段草稿

**现状。** 贴一段 → 建议落到哪几场 → 人点「写入此框」。正史仍须另点。文件：`Dialogs.tsx` 丢草稿框。

**GitHub 最佳例。** plotbunni `ImportOutlineModal.jsx` 导入大纲（替换或追加）。NovelForge 拆书工作流会自动落卡。

**差距判定。** **已优于** 一贴即正史。拆开建议仍偏素，但产品要的就是人点才进框。

**改造。** P2：建议条上写出「建议进哪一格」。不挡主路。

### 7. 侧栏规定情境五块

**现状。** `/api/circumstances` 已经带回上场转折、世界账、知情缺口、信错、读者知道的、未收伏笔。前端 `loadSit` 拼成一句塞进 `data-testid="sidebar"`。伏笔建议按钮是摆设。文件：`store.tsx` `loadSit`；`ScenePage.tsx` 侧栏顶。

**GitHub 最佳例。** FleshNote Entity Inspector 分块展示「谁知道什么」。bibisco 场景页把人物/地点/动机分栏。NovelForge 章节右侧上下文面板。

**差距判定。** 有差距。账已经算出来了，人看见的是一长串，不是五块。

**改造。** P1：仍保留原来那句给旧测试；另外按五块排：本场任务、上场转折、世界账、人物账（含不知/信错）、读者账、未收伏笔最多 5。建议按钮能忽略即可，不挡写入正史。

### 8. 档案页与拖拽在场 / 拿掉

**现状。** 左栏本页实体，可拖到卡上变成在场。点名字开档案。档案：基本设定可填，出场/情状只读，已挂场不能从设定删。后端 `POST /api/presence` 已支持 `action: "add"|"remove"`，正史拿掉会走确认变更。**前端没有拖回、没有 Delete 拿掉。** 芯片只是字，不能拖、不能点。文件：`LeftRail.tsx`、`Stripboard.tsx` 芯片、`DossierPage.tsx`、`setting_api.rs` `set_presence`。

**GitHub 最佳例。** plotbunni 概念卡拖到场景；dnd-kit 拖放；FleshNote `@mention` 挂实体。bibisco 点角色进档案。

**差距判定。** 有差距。产品写明「标记拖回左栏即从这场拿掉」，现在拖上去能加、拖回来不能拿。这是打开书会卡住的事。

**改造。** P0：芯片可拖回左栏拿掉（草稿立刻拿；正史出确认变更）。P1：点芯片开档案；选中芯片按 Delete 拿掉。不重编译 rust。

### 9. 出场矩阵

**现状。** 看法「出场」：人×列，实心在场 / 空心草稿或只被提到。点格跳该列。改在场仍回分场条拖。文件：`LookRail.tsx` `OccupancyLook`。

**GitHub 最佳例。** manuskript 故事线谁在哪场。没有更强的开源出场矩阵。

**差距判定。** **已达最佳**（只读、点跳、不在这里改库）。

**改造。** 无改造。

### 10. 连线图

**现状。** 看法「关系」：先选一个人，周围辐射节点。实线=设定关系，虚线=场上变过，淡=同场。点节点开档案或跳那场。拖边被挡住。文件：`LookRail.tsx` `RelationsLook`。

**GitHub 最佳例。** twinejs 故事地图可拖节点连线。FleshNote Sketchboards。xyflow 节点图（未进 12 清单，仅作图库参考）。

**差距判定。** 有差距，但是产品要的「只读、选中人才画」。Twine 那种可改图会变成第二份库，不抄。辐射图在人多时挤，属观感。

**改造。** P2：人多时换更疏的排布。不把连线改成可写。

### 11. 讲述序透镜

**现状。** 更多里「按读序排」。只改中栏排列和导出顺序。文件：`Topbar.tsx` `reading-order`；导出测过读序。

**GitHub 最佳例。** 开源小说工具几乎没有「故事时 vs 读序」两套排。Twine 是图不是时间轴。

**差距判定。** **已优于**（这是这本书自己的看法，别人没有对标物）。

**改造。** 无改造。

### 12. 命令面板

**现状。** `/` 或 ⌘K 打开。分组：跳 / 写 / 看 / 结构 / 书。搜字过滤。点按钮执行。没有空态、不能用方向键走、没有别名。文件：`CommandPalette.tsx`。

**GitHub 最佳例。** cmdk：空态、分组、keywords、嵌套页 Escape 回上层。kbar：Ctrl+n/p、快捷键展示。

**差距判定。** 有差距。面板在，但只能鼠标点，搜不到时一片空白。

**改造。** P0：空态「没有这条命令」；上下键走、回车执行、Esc 关掉；搜时也看别名（书架=书单，写下一场=n）。P1：条目旁标已有快捷键。嵌套页 P2，不在这轮做。不新装 npm 包（本机内存不够），按 cmdk 的交互自己写。

### 13. 纯键盘全流程

**现状。** ⌘K 面板；Alt+1–6 列数；`[` `]` 平移；左右箭头换场；空格侧开/整页；N 本场任务；A 加人；T 时间轴；L 逻辑线；Esc 层层收；⌘Z 撤草稿变化。文件：`store.tsx` `onKey`。面板打开时左右箭头已让路，其它键还可能抢。

**GitHub 最佳例。** kbar / cmdk 键盘优先；bibisco TAB/ENTER/ESC。

**差距判定。** 有差距。主干快捷键在，面板内不能键走，打开面板时 `[` `]` `n` 仍可能误触。

**改造。** P0：面板打开时只把键交给面板（Esc 关、⌘K 切换）。P1：Delete 拿掉选中芯片。不另做全页快捷键说明书。

### 14. 疏 / 中 / 密列数档位

**现状。** 疏/中/密 = 2/4/6。−/+ 钳 1–6，到头灰掉。1–2 展开动作对白内心；3–4 转折摘要；5–6 场次在场黄点。文件：`Topbar.tsx`、`Stripboard.tsx` 密度分支。

**GitHub 最佳例。** 无同类「本页可见列 1–6」。看板列数不限。

**差距判定。** **已达最佳**（这是已拍板，不是没追上 GitHub）。

**改造。** 无改造。

### 15. 导出 Markdown

**现状。** 预览、含草稿开关、标明正史 vs 草稿、可读序。只有 `<pre>`，没有「下载这个文件」。文件：`Dialogs.tsx` 导出框。

**GitHub 最佳例。** plotbunni `ExportModal.jsx` 真下 .md / .txt，可选目录。novelWriter / bibisco 导出多种格式。

**差距判定。** 内容合同已达（含草稿、标状态）。差在人没法把预览存成文件。

**改造。** P1：预览出来后「下载 .md」。不导出回写正史。

### 16. @ 与写入正史联动

**现状。** 动作/对白/内心里 `@` 弹出名单，点了写进字并加人在场。写入正史仍须另点。文件：`ScenePage.tsx` `GrowField` mention。

**GitHub 最佳例。** novelWriter `@tag` 交叉引用；FleshNote `@mention`；NovelForge `@DSL`。

**差距判定。** **已达最佳**（点名加人，不自动正史）。

**改造。** 无改造。

### 17. 删已正史影响清单

**现状。** 删已正史走确认变更，清单含故事时间空洞、后续规定情境、知情、伏笔、在场连续性、算出这一刻、第几次写入正史不重编号。文件：`ScenePage.tsx` `delete-canon`；e2e `ui-contract.spec.ts` 验过清单原文。

**GitHub 最佳例。** plotbunni / manuskript 删章只确认，不算后面的账。

**差距判定。** **已优于**。

**改造。** 无改造。

### 18. 伏笔埋 / 推 / 兑 / 废

**现状。** 场页「伏笔四件事」下拉加操作，非法组合会挡住。侧栏「建议本场对伏笔做哪一件」是摆设。命令面板能跳到伏笔档案。文件：`ScenePage.tsx` `PromiseBlock`；`CommandPalette.tsx`。

**GitHub 最佳例。** FleshNote Twist tracking。没有开源把「埋推兑废」做成这场必须发生的一件事。

**差距判定。** 主路径（人自己选做哪一件）已达。建议按钮未接上，不挡写入正史，属辅助。

**改造。** P2：建议真的给出一件可忽略的事。本轮不强做。

## 分歧与建议（GitHub 和已拍板打架时）

这些 **不改方向**，只记下来：

1. **看板拖完立刻改列**（planka / wekan）vs 我们「确认变更才写库」。保持确认。故事时间重叠、在场连续性不是看板能随便拖的。
2. **vis-timeline 当主面** vs 分场条主面。保持分场条。只抄细条拖窗口。
3. **Twine 可改节点图** vs 连线图只读。保持只读。
4. **NovelForge / 拆书工作流自动落卡** vs 「写入正史必须人点」。保持人点。
